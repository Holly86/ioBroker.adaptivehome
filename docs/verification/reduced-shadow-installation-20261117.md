# Reduced read-only installation preparation

The private source-only installation package uses unchanged published Beta 7. Its separate
file reader has no device, network, lifecycle or legacy-store write interface. Private paths,
identities, configuration, backup archives and deployment tooling remain outside public files.

## Verification

- File-reader, source-normalization, bounded installation, interrupted-copy recovery, output
  ownership and rollback contracts passed in isolation. Stale, absent, conflicting or future
  evidence cannot become a fresh negative value. Original human-request times and deadlines
  remain distinct from evaluation time.
- Actual js-controller 7.2.5 registered the new adapter disabled, ran the unchanged package
  with a source-only configuration, and removed its package, instance, host registration and
  Admin files. Existing installed module bytes and legacy objects remained unchanged.
- The rollback retained a newer human value outside the new namespace and refused a newer
  configuration inside it. Targeted root package metadata was restored byte for byte.
- The official restoration procedure restored a copied existing private backup without
  starting legacy device adapters. A subsequent official online backup was restored in a
  second network-isolated installation. Expired ephemeral states were distinguished from
  persistent state loss.
- The reader ran in an isolated container with read-only inputs and only its new output
  writable. Attempts to write the inputs, code mount and root filesystem were denied. The
  existing target runtime image also passed an isolated pure expiry/freshness probe without
  access to household volumes or network.

The source-only profile contains no registered control functions, confirmed actuator bindings,
write mappings, native actor transports, notification routes or enabled data exporter. The full
rule reference stays separate for local comparison. Observe mode alone is not a write barrier.

## Scope

These are preparation, restore and isolated runtime checks, not a production deployment or
physical acceptance. No production service restart or configuration change was requested and
no actuator write was issued. Production deployment clearance remains subject to a separate
live baseline-drift check. A later source-only installation still requires a fresh verified backup,
an unchanged-current-state check and a separately requested maintenance execution. Subsequent
live shadow observation and physical ownership/expiry/handoff acceptance remain open.
